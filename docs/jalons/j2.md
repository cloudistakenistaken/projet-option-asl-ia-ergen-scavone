## Procédure de reconstruction

Depuis la racine du dépôt, sur une machine disposant des prérequis système
indiqués dans le README :

```bash
bash scripts/setup.sh
```

Le script enchaîne les étapes suivantes :

1. création ou réutilisation de `.venv` et installation des dépendances ;
2. installation d'Ollama si nécessaire et vérification de son serveur local ;
3. téléchargement et contrôle de l'empreinte de Qwen ainsi que du cache E5 ;
4. ingestion du corpus et synchronisation de l'index Chroma ;
5. lancement des tests unitaires et d'intégration ;
6. démarrage de l'API avec `make serve` si toutes les étapes réussissent.

Le script affiche ensuite une requête HTTP de démonstration. Dans un deuxième
terminal, elle peut être exécutée avec :

```bash
curl --fail http://127.0.0.1:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"Le VPN est-il obligatoire en télétravail ?","top_k":2}' \
  | python3 -m json.tool
```

Une reconstruction réussie doit montrer l'installation sans erreur, l'index
créé, la réussite des tests et une réponse HTTP contenant une source pertinente.

## Mesure des temps de réponse

Les deux essais du 23 octobre ne sont pas utilisés comme mesure de performance.
Nous avons fixé cinq questions représentatives du corpus, effectué un
échauffement par question, puis lancé cinq exécutions mesurées par question
(soit 25 requêtes `POST /ask`). Les paramètres étaient `top_k=2`, température
`0`, graine `42`, modèle local `qwen2.5:3b`, et la durée mesurée est le temps
aller-retour HTTP, hors échauffement.

Machine utilisée : WSL2 Linux sur un Intel Core i7-13620H (13e génération),
architecture x86_64, Python 3.14.4, avec une NVIDIA GeForce RTX 4060 Laptop de
8 188 MiB ; Ollama indiquait toutefois une exécution à 100 % CPU pour cette
mesure. Le noyau était `6.18.58.1-microsoft-standard-WSL2`.

Configuration mesurée :

| Élément | Valeur |
| --- | --- |
| Endpoint | `http://127.0.0.1:8000/ask` |
| Génération | Ollama local, `qwen2.5:3b`, digest `357c53fb…c9e4b` |
| Contexte / sortie maximale | `num_ctx=4096` / `num_predict=384` |
| Température / graine | `0` / `42` |
| Embeddings | `intfloat/multilingual-e5-small`, révision `614241f6…cc418b3` |
| Recherche | Chroma, distance cosinus, `top_k=2` |
| Découpage des documents | 220 tokens, recouvrement de 32 tokens |
| Corpus / collection | corpus Novalys, `novalys-baseline` |
| Timeout Ollama | 120 s |

Jeu de données utilisé : 3 documents Markdown chargés depuis
[`data/corpus`](../../data/corpus/), dont 2 publics — [congés](../../data/corpus/public/conges.md)
et [télétravail](../../data/corpus/public/teletravail.md) — et 1 document
confidentiel, correspondant aux données privées fictives du scénario —
[projet Aurore](../../data/corpus/confidentiel/aurore.md). Les questions couvrent
les congés, le télétravail, le VPN et le budget Aurore. Les documents publics
décrivent également le report des congés, le portail RH, les jours de présence,
la prévenance et l'authentification multifacteur. Le document confidentiel
ajoute l'objectif d'Aurore, l'équipe pilote, la ventilation du budget et la
phase pilote. La preuve JSON conserve pour chaque document le chemin, le titre,
la taille, le nombre de mots, le SHA-256 et les thèmes associés.

| Mesure | Résultat |
| --- | ---: |
| Exécutions mesurées | 25 (5 questions × 5) |
| Médiane | 1 877,51 ms |
| Q1 – Q3 | 1 750,81 – 3 913,04 ms |
| Dispersion (IQR) | 2 162,23 ms |
| Minimum – maximum | 1 598,05 – 4 777,99 ms |
| Moyenne | 2 760,10 ms |

Le maximum isolé explique l'écart entre moyenne et médiane ; la médiane et
l'IQR sont donc les indicateurs retenus pour caractériser cette série. Les
questions, les temps individuels et la commande de mesure sont conservés dans
la [preuve JSON de latence](../preuves/2026-11-18/j2-latence.json) et le
protocole est reproductible avec le [script de benchmark](../../scripts/benchmark_latency.py).

## État des preuves

Le script a été ajouté, sa syntaxe Bash a été vérifiée et une requête réelle
sur le VPN a retrouvé `public/teletravail.md` avec une réponse correcte. Le
lancement des tests unitaires dans l'environnement de travail n'a pas renvoyé
de résultat avant le délai disponible. Nous ne déclarons donc pas encore la
reconstruction complète comme validée : il faut rejouer la commande ci-dessus
sur l'environnement de référence et conserver sa sortie (ce qui a marché dans nos machines respectives).

Les modifications de cette procédure sont décrites dans le [journal commun du
17 novembre](../journal/2026-11-17.md) et dans les [carnets individuels](../individuel/).
